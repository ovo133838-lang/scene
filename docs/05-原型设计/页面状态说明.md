## 二、用户端（buyer.html）页面与状态

### 2.1 商品列表
- 展示：在售商品、价格（分→元）、当前可售数量。
- 状态：商品A 可售 5 件（活动紧张）、商品B 可售 10 件。
- 对应：FR-101。

### 2.2 商品详情
- 展示：商品图、价格、可售数量、数量选择（1～2 件）、库存紧张提示。
- 操作：立即购买 → 确认订单。
- 对应：FR-102、BR-01。

### 2.3 确认订单
- 展示：商品、单价、数量、小计、应付金额（下单时价格快照）。
- 提示：提交占用库存，10 分钟未付款释放。
- 操作：提交订单（库存不足则失败提示）→ 支付页。
- 对应：FR-102、BR-01、BR-02。

### 2.4 支付页（支付宝沙箱收银台示意）
- 展示：应付金额、订单号、扫码示意（沙箱网关地址）。
- 操作：「我已付款（模拟回调成功）」→ 订单状态改为待发货；「暂不支付」→ 保留待付款。
- 幂等：待发货订单重复支付提示"重复通知已幂等忽略"。
- 对应：FR-104、BR-03、BR-04。

### 2.5 我的订单（列表）
- 覆盖全部 8 种状态：待付款、待发货、退款申请中、退款失败、已退款、已发货、已关闭、支付异常。
- 操作：进入详情。
- 对应：FR-103。

### 2.6 订单详情（状态驱动的操作区）
| 状态 | 操作/展示 |
| --- | --- |
| 待付款 | 去支付 / 取消订单（取消后变已关闭并释放库存） |
| 待发货 | 申请退款（→ 退款申请中，暂停发货） |
| 退款申请中 | 展示"待客服审核，发货已暂停" |
| 退款失败 | 展示"退款失败，客服跟进重试中" |
| 已退款 | 展示"退款成功，库存已恢复" |
| 已发货 | 展示承运方 + 运单号 |
| 已关闭 | 展示"已关闭，库存已释放" |
| 支付异常 | 展示"超时关闭后收到支付，已转异常待客服退款" |
- 对应：FR-103/105/106/107/108、BR-05/06/07。

### 2.7 退款申请页
- 填写整单退款原因 → 提交 → 状态改"退款申请中"。
- 对应：FR-106、BR-05。

## 三、管理端（admin.html）页面与状态（RBAC）

> 侧边栏菜单随角色切换，不同角色看到不同菜单；无权限资源在侧栏标注"正式系统返回 403"，并提供 403 拦截页演示。

### 3.1 运营角色
| 菜单 | 说明 |
| --- | --- |
| 商品管理 | 上下架切换（下架不影响已下单订单金额），对应 FR-201、BR-01 |
| 库存看板 | 商品可售数量统计，对应 FR-202 |
| 交易汇总 | 已收款/已退款/已发货/异常支付四类统计 + 全量订单记录，对应 FR-203、BR-08 |

### 3.2 仓库·商家角色
| 菜单 | 说明 |
| --- | --- |
| 可发货订单 | 仅列出"待发货"（退款申请中的暂停发货，不在此列表），发货登记弹窗填承运方+运单号 → 变已发货，对应 FR-301/302、BR-07 |
| 已发货记录 | 承运方 + 运单号列表，对应 FR-303 |
| 发货数据 | 待发货/已发货/总数只读统计，对应 FR-303 |

### 3.3 客服角色
| 菜单 | 说明 |
| --- | --- |
| 退款审核 | 退款申请中列表，同意（→退款处理中）/拒绝（必填原因→恢复可发货），对应 FR-401、BR-05 |
| 异常支付 | 迟到支付列表，核实并退款（不恢复库存），对应 FR-402、BR-04/06 |
| 退款重试 | 退款失败列表，重试→已退款并恢复库存，对应 FR-403、BR-06 |

### 3.4 越权与鉴权演示
- 仓库角色无权访问"退款审核/异常支付/商品管理"等资源（侧栏标注 + 403 拦截页）。
- 顶部角色切换按钮模拟"不同账号登录"。
- 正式系统：JWT + RBAC，前端隐藏菜单 + 后端接口双重校验，禁止改请求中用户编号越权（对应 §2.3 鉴权硬性要求）。

## 四、五组场景在原型中的还原对照

| 场景 | 原型还原路径 |
| --- | --- |
| 1 正常成交 | 运营「商品管理」上架 → 买家购买 → 支付成功 → 仓库「发货登记」→ 买家看运单 → 运营「交易汇总」 |
| 2 缺货与弃单 | 买家多次下单商品A 库存递减 → 待付款订单取消/超时释放 → 库存恢复再购 |
| 3 售前退款 | 买家「申请退款」→ 仓库可发货列表无该单 → 客服「同意」→「退款重试」成功 → 库存恢复 |
| 4 迟到支付 | 订单「已关闭」→ 客服「异常支付」出现该单 →「核实并退款」→ 运营「交易汇总」核对不二次恢复库存 |
| 5 操作竞争与越权 | 仓库访问客服菜单被 403 拦截；买家端仅本人订单；并发冲突在正式系统用状态机/行锁收敛 |

---

## 五、原型局限与后续迁移

1. 原型为纯前端 mock，数据刷新即重置，不代表后端真实数据一致性。
2. 并发抢购（20 请求）、支付通知幂等、退款与发货并发收敛等，在开发阶段由后端状态机 + 数据库锁/事务实现，原型仅作流程与状态示意。
3. 用户端后续迁移 Vue3 + Element Plus，管理端迁移 vue-element-admin，视觉与交互保持一致。
