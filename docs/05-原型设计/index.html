题目01 电商订单交易、发货与售前退款系统 · 原型

岗位来源：北京易博中天｜Golang（短期1-3个月）　|　原型版本 V1.0　|　2026-11-15

原型说明

演示数据说明：本原型使用 mock 演示数据，全部页面可点击、可跳转、可切换关键业务状态，用于还原需求文档（PRD）中的角色操作与异常分支，不连接后端与真实支付。
操作约定：页内点击按钮会产生真实的状态流转反馈（如"取消订单→已关闭""同意退款→退款处理中"），刷新页面后数据重置为初始演示态。
鉴权约定：正式系统所有操作须 JWT 鉴权 + 角色/资源授权，原型中通过"角色入口隔离 + 越权操作提示"示意该约束（见管理端的越权演示）。

五组完整工作场景 · 演示导航

场景1活动正常成交

运营上架商品 → 买家购买付款 → 仓库发货 → 买家查询运单 → 运营核查收款与库存。

演示：管理端-运营「商品管理」上架 → 用户端「购买商品A」→ 模拟支付成功 → 管理端-仓库「发货登记」→ 用户端「查看运单」→ 管理端-运营「交易汇总」

场景2缺货与弃单

商品A 仅剩 5 件，20 个并发下单争抢 → 部分订单未付款关闭 → 其他买家购买释放的商品。

演示：用户端多次下单商品A（库存递减）→ 待付款订单「取消/超时」→ 库存恢复可再购；并发抢购在正式系统用压测脚本验证

场景3售前退款

买家付款后申请 → 仓库尝试发货受限 → 客服批准 → 首次退款失败、再次成功 → 订单与数量恢复一致。

演示：用户端「申请退款」→ 管理端-仓库该单不可发货 → 客服「同意退款」→「退款失败」→「重试成功」→ 库存恢复

场景4迟到支付

订单先关闭 → 支付成功通知到达 → 客服从异常列表发现 → 发起退款 → 运营确认无重复释放和重复退款。

演示：用户端订单超时关闭 → 管理端-客服「异常支付」列表出现该单 → 「发起退款」→ 运营「交易汇总」核对无二次恢复库存

场景5操作竞争与越权

退款申请与发货并发、重复支付和退款通知、越权查看或处理他人订单，均须有明确结果。

演示：仓库角色尝试访问客服菜单被拒 → 买家端只能看本人订单；并发冲突在正式系统用行锁/状态机收敛
