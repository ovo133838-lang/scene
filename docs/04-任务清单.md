## 二、任务详细规格

### T0 约束与环境准备（准备）
- **目标**：项目级 `AGENTS.md` 生效；两个自编 Skill 就绪；环境与配置方案确定。
- **输出**：`AGENTS.md`（含 3 个 Agent 职责、2 个 Skill 内嵌、业务流程要求）、`skill-业务约束检查.md`、`skill-验收检查.md`、环境记录。
- **完成条件**：AGENTS.md 明确开发/测试/验收 Agent 职责与边界；Skill 含七要素；支付宝沙箱密钥登记于本地 `configs/` 且已加入 `.gitignore`。
- **技术要点**：本阶段由学生主导，开发 Agent 业务开发开始前必须已存在本文件。

### T1 项目骨架与数据库（开发）
- **目标**：可运行的最小 Gin 骨架 + MySQL 表结构 + 预置数据。
- **输出**：`go.mod`、`cmd/server/main.go`、`internal/` 目录骨架、`migrations/` DDL、`configs/config.toml`、种子数据。
- **完成条件**：`go build` 通过；服务可启动；MySQL 连接正常；Redis 连接正常。
- **数据要点**（详见需求 §6）：`product`、`order`、`payment`、`refund`、`shipment`、`payment_abnormal`、`user`、`role_permission` 八张表；金额字段 `BIGINT` 存分；`channel_txn_no` 唯一索引；订单状态用字符串枚举。
- **预置数据**：商品A「XX 品牌无线蓝牙耳机（标准款）」10000 分 / 可售 5 件；商品B「YY 便携式蓝牙音箱」8000 分 / 可售 10 件；买家 3 个、运营 1 个、仓库(商家) 1 个、客服 1 个。
- **技术要点**：Gin + MySQL(8.x) + Redis(7.x)；配置从 `configs/config.toml` 读取；支付宝沙箱密钥不硬编码。

### T2 鉴权与 RBAC（开发）
- **目标**：JWT 签发/校验中间件 + 角色权限 + 资源归属校验。
- **输出**：`internal/auth`（JWT、登录、中间件、RBAC 守卫）。
- **完成条件**：未带 token 或越权请求返回 401/403；买家只能访问本人订单；后台角色只能访问权限矩阵内功能。
- **预置账号**：买家 buyer1/buyer2/buyer3、运营 operator、仓库 warehouse、客服 service。
- **技术要点**：身份一律取会话 token，不信任请求参数中的用户编号（§2.3 硬性）。

### T3 商品模块（开发）
- **目标**：商品上下架、改价、库存维护、可售数量查询。
- **输出**：`internal/product`。
- **完成条件**：下架商品不可购买；改价/上下架不改变已存在订单金额（价格快照）；可售数量=总库存−已占用。
- **接口**：`GET /api/products`、`POST /api/admin/products/{id}/shelf`、`PUT /api/admin/products/{id}`。

### T4 订单与库存占用（开发）
- **目标**：下单原子占用库存（防超卖）、订单状态机、取消、10 分钟超时关闭释放。
- **输出**：`internal/order`（状态机、占用/释放、超时清扫）。
- **完成条件**：
  - 20 并发下单争抢 5 件库存，恰好成功 5 件对应的数量，无超卖；
  - 取消/超时关闭释放占用，重复关闭不多释放；
  - 超时判断用服务端时间。
- **状态机**：待付款→(支付成功)待发货→(发货)已发货；待付款→(取消/超时)已关闭；待发货→(申请退款)退款申请中→(客服同意)退款处理中→(退款成功)已退款 / (失败)退款失败；待发货→(申请退款)退款申请中→(客服拒绝)待发货；已关闭→(迟到支付)支付异常→(客服退款)已退款。
- **技术要点**：库存占用用事务 + 条件 `UPDATE ... WHERE stock >= qty` 或 `SELECT ... FOR UPDATE`；超时用 Redis 过期键或定时清扫任务；状态迁移集中在单一 transition 函数 + 守卫 UPDATE 幂等。

### T5 支付链路（沙箱 + 回调网关）（开发）
- **目标**：支付宝沙箱真实支付 + 异步通知验签 + 可控回调网关（异常注入）+ 幂等 + 迟到支付。
- **输出**：`internal/payment`（发起、验签、通知处理、回调网关）、`internal/mockpay`（可控模拟）。
- **完成条件**：
  - 发起支付生成沙箱收银台链接；沙箱异步通知验签通过后订单变待发货并落流水；
  - 重复通知不重复记款；同一 `channel_txn_no` 不归属两个订单；
  - 金额不符/未知订单/验签失败可查询处理结果；
  - 超时关闭后收到的成功通知进入"支付异常待处理"，不恢复订单、不重占库存；
  - 回调网关可注入：成功/失败/超时/重复/迟到/验签失败/金额不符/未知订单。
- **接口**：`POST /api/pay/create`、`POST /pay/notify`（沙箱真实回调）、`POST /api/admin/pay/mock-notify`（可控网关）。
- **技术要点**：验签用支付宝公钥（公钥模式）；回调幂等依赖 `channel_txn_no` 唯一索引；迟到支付走独立异常记录。

### T6 退款链路（开发）
- **目标**：售前退款申请、客服审核、渠道退款、失败重试、迟到支付退款（不恢复库存）。
- **输出**：`internal/refund`。
- **完成条件**：
  - 已付款未发货订单可申请整单退款，申请期暂停发货；
  - 客服同意→渠道退款成功→恢复可售数量；拒绝→恢复可发货；
  - 渠道明确失败保留待处理记录，客服可重试；
  - 迟到支付退款**不恢复**库存（已释放过）。
- **接口**：`POST /api/orders/{id}/refund`、`POST /api/admin/refunds/{id}/approve`、`POST /api/admin/refunds/{id}/reject`、`POST /api/admin/refunds/{id}/retry`、`POST /api/admin/pay-abnormal/{id}/refund`。
- **技术要点**：退款类型字段区分"售前/迟到支付"；售前成功才恢复库存，迟到支付退款不恢复。

### T7 发货链路（开发）
- **目标**：可发货订单查询、一次性发货登记、退款与发货并发唯一结果。
- **输出**：`internal/shipment`。
- **完成条件**：仅合法待发货订单可发货；每单登记一次；退款申请中不可发货；退款与发货并发只形成一种合法结果。
- **接口**：`GET /api/admin/ship/pending`、`POST /api/admin/ship/{id}`、`GET /api/admin/ship/shipped`。
- **技术要点**：发货前置校验订单状态=待发货（且无退款申请中）；行锁/状态守卫确保与退款并发唯一收敛。

### T8 运营汇总（开发）
- **目标**：按订单查询收款/退款/发货/异常记录，商品汇总。
- **输出**：`internal/report`。
- **完成条件**：可查已收款/已退款总额、已发货数、异常支付数；异常记录不因改订单状态消失。
- **接口**：`GET /api/admin/summary`、`GET /api/admin/orders/{id}/records`。

### T9 用户端前端（开发）
- **目标**：按原型 buyer.html 实现 Vue3 + Element Plus 用户端，**并入后端 `web/` 目录**，构建产物经 `go:embed` 打进单二进制（同源部署，不单独建仓）。
- **输出**：`web/` 目录（Vue3 源码 + dist 构建产物）。
- **完成条件**：商品浏览、下单、支付、订单查询、取消、退款申请、运单查询可完整走通；单二进制部署后页面同源可用。

### T10 管理端前端（开发）
- **目标**：按原型 admin.html 实现 vue-element-admin 管理端（运营/仓库/客服 RBAC）。
- **输出**：`frontend-admin/` 工程。
- **完成条件**：三角色菜单隔离；运营商品管理/汇总、仓库发货、客服退款审核/异常支付/重试可用。

### T11 单元测试与覆盖率门禁（测试）
- **目标**：核心业务包单元测试 ≥85%。
- **输出**：`*_test.go`、覆盖率报告。
- **完成条件**：整体与 `internal/order`、`internal/payment`、`internal/refund`、`internal/shipment` 分别 ≥85%；`go vet` 通过。

### T12 集成/接口测试（测试）
- **目标**：支付回调矩阵、退款矩阵、迟到支付、越权。
- **完成条件**：回调验签/金额/未知/重复/迟到全部覆盖；退款成功/失败/重试/迟到支付不恢复库存覆盖；越权 401/403 覆盖。

### T13 并发与竞争测试（测试）
- **目标**：20 并发下单、退款 vs 发货并发、重复通知。
- **完成条件**：并发结果确定无超卖；退款发货并发唯一结果；可重复执行。

### T14 质量检查与竞态检测（测试）
- **目标**：`gofmt`、`go vet`、`go test -race`。
- **完成条件**：全部通过；失败禁止进入合并。
